**Day 14: How the Top 3 Mold Sites Are Built**

I looked under the hood of the three highest ranking contest sites on the mold query. Three completely different approaches, all within seven positions of each other.

**Site A, position 10**

The developer build. Static site on Cloudflare's edge, loads in a third of a second, never goes down. 94 pages, mostly question style guides. Three author pages with bios. Full business schema with an address, hours, map link and seven social profiles. Every page has a plain text version for AI crawlers. Zero analytics installed. One Facebook page, which is sitting at position 8 on its own.

**Site B, position 15**

The referral build. Says right on the page it is a lead gen site, not a contractor. Runs as an app on a single cloud server with no caching in front of it. That server hosts six other contest domains and has gone down twice this week. It is unreachable as I write this. Google is ranking it from memory. Its team page is the URL that ranks, not the homepage.

**Site C, position 17, debuted today**

The page generator build. 107 flat HTML pages, no JavaScript, no images, no fonts, one stylesheet. Every township times every service. Schema tags each area as a Township or Borough instead of a City. Same contestant has a 120 page radon site built the exact same way. Slow server, but it landed in the points on day one.

**What all three share**

- Business name is the keyword
- Static pages, no WordPress
- Phone number and street address in the schema
- Township level location pages
- FAQ schema on the homepage
- No analytics at all
- Nothing off site except one Facebook page

**The takeaway**

A fancy stack, a plain stack and a broken stack are all on page 2 together. The tech is not what's separating them. The name, the schema, the page count and the location pages are doing the work.

Build it static. Name it the keyword. Put a real address in the schema. Ship 50 plus pages. Then worry about everything else.
